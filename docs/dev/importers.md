# Importers

Every import goes through one pipeline in `importers/pipeline.py`:

```text
read -> detect preset -> apply preset -> map vehicles -> dedupe -> preview -> commit (one transaction, one batch)
```

The web UI calls only the pipeline. There is no code per format: the layout of a file is described by a **preset**, a TOML file read by one engine.

## Modules

| Module | Role |
|---|---|
| `standard.py` | The standard CSV format: field definitions, example, Data Package descriptor. Docs are generated from it. |
| `importers/presets.py` | The `Preset` dataclasses, the key table, `load_preset` (validates, names the bad key), the TOML writer, shipped presets (`src/glovebox/presets/*.toml`) and user presets (database table `preset`). |
| `importers/engine.py` | Pure, no database. `read_file` (encoding, delimiter, ZIP members, `## Section`, header row), `score` (how well a preset fits), `apply` (skip rules, mapping, value maps, number and date parsing, units) giving canonical records, row errors and questions. |
| `importers/base.py` | Canonical record types, `RowError`, `Question`, `Answers`, and the locale helpers. |
| `importers/pipeline.py` | `detect_preset`, `preview_import`, `commit_import`, `undo_batch`: vehicle mapping, duplicates, stations, companion tables, the single transaction. |

`detect_preset` scores user presets first, then the shipped ones; the best score of at least 0.5 wins. On a tie the first user preset wins, and among shipped presets `fuelio-fillups` (a Fuelio backup fits both Fuelio presets). With no match the mapping starts from the standard field names (`engine.fallback_preset`).

## Companion tables and backups

A ZIP member named `vehicles.csv` or `stations.csv` (with a `name` column and no `date` column) is not a records table. `engine.read_file` returns it as `SourceFile.vehicles` / `.stations`, read with the fixed standard layout and without the preset. The pipeline creates missing vehicles and stations and only fills empty details of existing ones (`CompanionChange` in the preview). A full backup is this plus `datapackage.json`: then `records.csv` is always read with the standard preset. One code path serves both.

## Preset files

Format and keys: [Presets](../user/presets.md) (generated by `uv run python -m glovebox.formatdocs`; `--check` runs in the tests). Example:

```toml
name = "My bank"
[format]
date_format = "%d.%m.%Y"
decimal_char = ","
[fields]
type = { value = "refuel" }
date = { column = "Datum" }
odometer_km = { column = "Stand" }
fuel_l = { column = "Liter" }
```

## Add a layout

No code change. Write the preset in the app (mapping step, then "Save as preset") or as a file in `src/glovebox/presets/`, add an anonymised fixture to `tests/fixtures/` and a case in `tests/test_presets_shipped.py`. Set `verified = true` only after checking against a real export. A shipped preset used for export needs `export = true` and no skip rules.

Notes: stations are created by name and location; a brand is only set when the file provides one. Duplicate keys are (vehicle, date, odometer, litres to 0.01) for refuels and (vehicle, date, category, amount) for expenses.
